# Resource Logs

## Overview

Resource Logs provide detailed diagnostic information generated by individual Azure resources.

Unlike Platform Metrics, Resource Logs capture events, operations, requests, and diagnostic information that help troubleshoot resource-specific issues.

Resource Logs are not collected by default and must be enabled using Diagnostic Settings.

---

# Key Characteristics

Resource Logs have the following characteristics:

- Resource-specific
- Not enabled by default
- Collected through Diagnostic Settings
- Can be sent to multiple destinations
- Support detailed troubleshooting
- Can be queried using KQL

---

# Typical Resource Logs

The available log categories depend on the Azure resource.

| Azure Resource | Example Log Categories |
|----------------|------------------------|
| Storage Account | Read, Write, Delete |
| Key Vault | AuditEvent |
| App Service | HTTP Logs, Console Logs, Application Logs |
| Application Gateway | Access, Performance, Firewall |
| Azure Firewall | Network Rule, Application Rule, DNS Proxy |
| Azure SQL Database | SQL Insights, Automatic Tuning |
| Azure Kubernetes Service | Control Plane Logs, Audit Logs |

---

# How Resource Logs Work

```text
Azure Resource
        │
        ▼
Resource Logs
        │
        ▼
Diagnostic Settings
        │
        ├──► Log Analytics Workspace
        ├──► Storage Account
        └──► Event Hub
```

Diagnostic Settings determine which log categories are collected and where they are sent.

---

# Diagnostic Categories

Each Azure resource exposes different diagnostic categories.

Example for an Application Gateway:

| Category | Description |
|----------|-------------|
| Access Log | Client requests processed by the gateway |
| Performance Log | Performance-related information |
| Firewall Log | Web Application Firewall events |

Always review the available categories before configuring Diagnostic Settings.

---

# Querying Resource Logs

When Resource Logs are sent to a Log Analytics Workspace, they can be queried using Kusto Query Language (KQL).

Example:

```kusto
AzureDiagnostics
| where ResourceType == "APPLICATIONGATEWAYS"
| take 10
```

The available tables depend on the connected resources and enabled log categories.

# Common Use Cases

Resource Logs are commonly used for:

- Troubleshooting application issues
- Investigating failed requests
- Auditing resource activity
- Security investigations
- Performance analysis
- Compliance reporting

---

# Resource Logs vs Platform Metrics

| Resource Logs | Platform Metrics |
|---------------|------------------|
| Detailed events | Numeric measurements |
| Event-based | Time-series data |
| Require Diagnostic Settings | Collected automatically |
| Queried using KQL | Displayed in Metrics Explorer |
| Ideal for investigations | Ideal for monitoring trends |

---

# Resource Logs vs Activity Log

| Resource Logs | Activity Log |
|---------------|--------------|
| Resource-level diagnostics | Subscription-level management events |
| Focus on resource behavior | Focus on administrative operations |
| Require Diagnostic Settings | Available automatically |
| Primarily data plane | Control plane |

---

# Best Practices

- Enable Resource Logs only for services that require monitoring.
- Send logs to a centralized Log Analytics Workspace.
- Review available log categories before enabling all of them.
- Monitor log ingestion costs, especially for high-volume resources.
- Use KQL to filter and analyze log data efficiently.
- Combine Resource Logs with Platform Metrics for comprehensive monitoring.
