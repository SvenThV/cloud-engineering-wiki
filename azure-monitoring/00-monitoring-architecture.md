# Azure Monitoring Architecture

## Overview

Azure Monitor is Microsoft's centralized monitoring platform for collecting, analyzing, visualizing, and acting on telemetry data from Azure resources, applications, virtual machines, and other connected services.

It provides a unified monitoring solution by combining metrics, logs, alerts, dashboards, and application monitoring into a single platform.

Azure Monitor helps answer questions such as:

- Is a resource healthy?
- Has a deployment changed something?
- Is an application performing as expected?
- Has an alert threshold been exceeded?
- What happened before an incident occurred?

# Monitoring Data Sources

Azure Monitor collects data from multiple sources.

| Data Source | Purpose |
|------------|---------|
| Platform Metrics | Performance metrics generated by Azure resources |
| Resource Logs | Detailed resource-specific events and diagnostics |
| Activity Log | Subscription-level management events |
| Guest OS | Operating system logs and performance counters collected via Azure Monitor Agent |
| Applications | Application telemetry collected by Application Insights |

---

# Core Components

Azure Monitor consists of several core services.

| Component | Purpose |
|----------|---------|
| Platform Metrics | Near real-time performance metrics |
| Activity Log | Subscription and management events |
| Resource Logs | Resource-specific diagnostic information |
| Diagnostic Settings | Forward logs and metrics to supported destinations |
| Log Analytics Workspace | Central storage and analysis of log data |
| KQL | Query language for log analysis |
| Azure Monitor Agent (AMA) | Collects guest operating system data |
| Data Collection Rules (DCR) | Define what data is collected |
| Alert Rules | Detect conditions requiring attention |
| Action Groups | Execute notifications or automated actions |
| Alert Processing Rules | Modify or suppress alerts |
| Application Insights | Application performance monitoring |
| Workbooks | Interactive monitoring dashboards |
| Service Health | Azure platform health events |
| Resource Health | Health status of individual Azure resources |

# Platform Monitoring vs Guest Monitoring

Azure Monitor collects information from different layers.

| Platform Monitoring | Guest Monitoring |
|---------------------|------------------|
| Managed by Azure | Collected from inside the operating system |
| No agent required | Azure Monitor Agent required |
| Resource availability | Windows/Linux events |
| CPU utilization | Event Logs |
| Network throughput | Performance Counters |
| Storage metrics | Syslog |

---

# Typical Monitoring Workflow

A common monitoring implementation follows these steps:

1. Enable monitoring for Azure resources.
2. Configure Diagnostic Settings.
3. Send logs to a Log Analytics Workspace.
4. Query data using KQL.
5. Create Alert Rules.
6. Configure Action Groups.
7. Build monitoring dashboards using Workbooks.

---

# Best Practices

- Use a centralized Log Analytics Workspace whenever possible.
- Enable Diagnostic Settings for important resources.
- Monitor both platform and guest operating system data.
- Prefer reusable Action Groups.
- Standardize monitoring across subscriptions.
- Deploy monitoring resources using Infrastructure as Code.
- Review log retention and ingestion costs regularly.
