# Dependencies, Artifacts and Caching

## Overview

By default, jobs in a GitHub Actions workflow run independently and in parallel.

GitHub Actions provides several features to coordinate jobs and improve workflow performance:

- `needs` defines dependencies between jobs.
- Artifacts allow files to be shared between jobs.
- Caching reduces execution time by reusing downloaded dependencies.

---

## Job Dependencies (`needs`)

The `needs` keyword creates a dependency between jobs.

A dependent job starts only after the required job has completed successfully.

Example:

```yaml
jobs:

  format:
    runs-on: ubuntu-latest

  validate:
    needs: format
    runs-on: ubuntu-latest
```

Execution order:

```text
Format
   │
   ▼
Validate
```

Without `needs`, both jobs would start at the same time.

---

## Multiple Dependencies

A job can depend on multiple jobs.

Example:

```yaml
jobs:

  format:
    runs-on: ubuntu-latest

  validate:
    runs-on: ubuntu-latest

  plan:
    needs:
      - format
      - validate
```

Execution order:

```text
Format ───┐
          │
          ▼
       Validate
          │
          ▼
         Plan
```

---

## Artifacts

Artifacts are files generated by one job and used by another job.

Typical examples include:

- Terraform plans
- Build artifacts
- ZIP packages
- Test reports
- Log files

Artifacts remain available after the workflow has finished.

---

## Upload Artifact

Example:

```yaml
- uses: actions/upload-artifact@v4
  with:
    name: terraform-plan
    path: terraform.tfplan
```

---

## Download Artifact

Example:

```yaml
- uses: actions/download-artifact@v4
  with:
    name: terraform-plan
```

---

## Artifact Workflow

```text
Job 1
│
├── terraform plan
│
└── upload-artifact
         │
         ▼
Job 2
│
├── download-artifact
│
└── terraform apply
```

---

## Caching

Caching stores frequently downloaded dependencies between workflow runs.

Unlike artifacts, caches are intended to improve performance rather than transfer files between jobs.

Typical cache contents include:

- Terraform providers
- Python packages (`pip`)
- npm packages
- Maven dependencies
- Gradle dependencies

---

## Cache Example

Example:

```yaml
- uses: actions/cache@v4
```

The cache is restored automatically if a matching cache key is found.

---

## Artifacts vs Caching

| Artifacts | Caching |
|------------|---------|
| Share files between jobs | Speed up future workflow runs |
| Created during a workflow | Reused across workflow executions |
| Intended for generated files | Intended for downloaded dependencies |
| Example: Terraform plan | Example: Terraform providers |

---

## Terraform Example

A common Terraform workflow:

```text
Job 1

terraform fmt
terraform init
terraform validate
terraform plan
        │
        ▼
Upload Terraform Plan
        │
        ▼
Job 2

Download Terraform Plan
terraform apply
```

---

## Best Practices

- Use `needs` only when jobs depend on each other.
- Keep independent jobs running in parallel.
- Use artifacts only for files that must be shared.
- Cache downloaded dependencies instead of generated files.
- Avoid caching the entire `.terraform` directory unless there is a specific requirement.
- Use descriptive artifact names.
